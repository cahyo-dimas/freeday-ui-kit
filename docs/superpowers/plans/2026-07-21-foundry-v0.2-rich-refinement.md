# Foundry v0.2 (Rich Refinement + Business Screen) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Naikkan look Foundry ke default "rich refinement" (validated via before/after mockup) dan tambah komponen untuk merakit satu layar bisnis nyata: app shell, table, modal, form controls.

**Architecture:** Semua lewat token (Tier 1→2→3). `tokens/build.mjs` **tidak berubah** — ia otomatis mem-flatten token baru & mem-bundle `src/components/*.css` baru (alfabetis). Interaktivitas via **native HTML** (`<dialog>`, `<select>`, `<input>`) + JS vanilla minimal hanya di docs. 0 dependency.

**Tech Stack:** CSS murni · `tokens.json` (DTCG-lite) · Node ≥ 20 (`node --test`) · native `<dialog>` · Google Fonts di docs (bukan di CSS terkirim).

**Referensi visual:** mockup before/after "rich" (artifact) — glow via `color-mix` warna aksi, `--shadow-lift`, gradient tombol halus, focus ring, badge `-strong` AA.

## Global Constraints

- Node ≥ 20; ESM; **ZERO dependency** (Node stdlib + `node --test`).
- Prefix kelas `fdy-`; BEM ringkas.
- **Token discipline (pragmatis, spec §9):** warna **selalu** token (termasuk `color-mix(... var(--color-*) ...)`); spasi skala pakai `--space-*`; literal lokal boleh (mis. `#fff 15%` di gradient, `rgba(255,255,255,.26)` inner-highlight, `1.5px`, `.35em`, `2px`).
- **Kontras WCAG AA** (teks & kontrol). Badge text pakai token `--color-*-strong` (nilai sudah diverifikasi lolos ≥4.5:1 di §Task 1).
- **Native-first (ARIA §11.3):** modal = native `<dialog>` (focus-trap/Esc/backdrop gratis); select = native `<select>`; checkbox/radio/switch = native `<input>` di-style; app shell = landmark `<header>/<nav>/<main>/<aside>` + skip-link + `aria-current="page"`.
- `prefers-reduced-motion: reduce` dihormati (animasi modal & transisi dimatikan).
- `dist/` di-commit. `build.mjs` tidak diedit di v0.2.
- Path relatif ke root repo. Branch: `feat/v0.2-rich-refinement`.
- Commit: Conventional Commits.

## Task 2: Button — rich (gradient + glow + press)

**Files:** Modify `src/components/button.css`; Modify `docs/index.html` (tak wajib, showcase lama tetap berlaku); generated `dist/foundry.css`.

**Interfaces:** Consumes `--color-primary`, `--color-danger`, `--shadow-1`. Kelas tetap: `.fdy-btn`, `--ghost`, `--danger`, `--sm`, `--lg`.

> **REVISI (AA, keputusan user 2026-07-21):** gradient dibalik jadi **gelap-ke-bawah** — atas = warna solid brand, bawah `color-mix(#000 …)`. Alasan: gradient terang-di-atas menembus WCAG AA di tombol danger light (teks putih di balik teks 4.03–4.39:1 < 4.5, karena `--color-danger` #dc2626 vs putih sudah hanya 4.83:1). Dengan gelap-ke-bawah, latar tak pernah lebih terang dari warna solid → AA aman di semua state (danger 4.83, primary 6.56). Konsekuensi: hover **tidak** lagi `filter:brightness()` (itu menerangkan fill & membocorkan AA lagi); hover diekspresikan lewat lift + glow lebih kuat. Glow + inner-highlight tetap → look tetap "rich". Konsisten primary & danger.
>
> **REVISI lanjutan (dark-mode danger):** gelap-ke-bawah membocorkan AA di **dark danger** karena skema v0.1 = bg merah-terang + teks gelap (`#f87171`/`#4a0f0f`) → menggelapkan bawah malah menurunkan kontras teks-gelap (bottom 4.35 < 4.5). Perbaikan (sesuai catatan v0.1 untuk v0.2): danger button jadi **merah tegas + teks putih di kedua mode**, seperti primary. Token baru `--color-danger-btn` (`{red.600}` #dc2626 light & dark; `--color-danger` biasa TETAP merah-terang untuk teks error/badge), dan `--color-on-danger` dark diubah `#4a0f0f` → `{slate.0}` (putih). Nilai AA final terverifikasi: light primary 6.56/danger 4.83, dark primary 4.89/danger 4.83 (naik ke arah bawah). `--color-on-danger` hanya dipakai tombol danger → aman diubah.
